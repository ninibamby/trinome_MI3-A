

Notre équipe est composée de 3 membres : Payet nino , Gil-Thellier Valentin, 
	

nous sommes 3 éleves avec des niveaux similaire en informatique, nous avons travaillé sur le projet FlipTech, un jeu de cartes développé en langage C.
Le but du jeu est de gérer des manches entre plusieurs joueurs, avec un système de pioche, de score et de conditions de fin de partie.

Ce projet nous a permis de mettre en pratique les notions de programmation en C de toute l année. Principalement la gestion de structures, de tableaux, de pointeurs et de fichiers.


Les principaux objectifs étaient de créer un jeu fonctionnel sur le terminal ,Gérer plusieurs joueurs simultanément,cree une pioche de cartes
calculer les scores automatiquement,sauvegarder les résultats dans un fichier texte,organiser correctement le code en plusieurs modules


Nous avons adopté une organisation par fonction, un faisait la fonction principale et les autre les plus petite fonction utile dans celle ci et pour finir 
nous avons repartie le travail pour l'affichage.


Chaque membre du groupe était responsable d’un ou plusieurs modules.

Nous avons utilisé une organisation progressive :
	1.	Structure du projet
	2.	Implémentation des bases (joueurs + cartes)
	3.	Gestion de la logique du jeu
	4.	Ajout des règles spéciales (doublons, Flip 7)
	5.	Sauvegarde des scores

⸻

4. Problèmes rencontrés

Plusieurs difficultés ont été rencontrées :

4.1 Gestion des pointeurs

La manipulation des pointeurs a été complexe, notamment pour :
	•	la pioche de cartes.
	•	la modification des structures joueurs.
	•	le passage d’arguments entre fonctions.

⸻

4.2 Segmentation fault

Nous avons rencontré plusieurs erreurs de type :
	•	accès mémoire invalide.
	•	mauvais passage de paramètres.
	•	confusion entre pointeur et structure.

⸻

4.3 Organisation du code

Au début, le code était peu structuré, ce qui rendait :
	•	le debug difficile.
	•	la compréhension du programme compliquée.

⸻

4.4 Gestion des fichiers

La sauvegarde des scores a nécessité :
	•	l’utilisation de fopen, fprintf, fclose.
	•	la gestion des noms de fichiers dynamiques.

4.4 L'affichage 

un affichage plaisant et agréable a été difficile à mettre en place :
	•	définir la largeur minimale d’affichage.
	•	la gestion des cartes et affichage en couleur.

⸻

5. Solutions apportées

Pour répondre à ces problèmes :
	•	Utilisation de Makefile pour compiler automatiquement le projet 
	•	Correction des erreurs de pointeurs (. vs ->)
	•	Ajout de vérifications (if NULL, contrôle scanf, pour améliorer la robustesse)
	•	Séparation du code en plusieurs fichiers .c et .h ( a aussi permit de clarifier notre code )
	•	Tests réguliers à chaque étape du développement

⸻

6. Résultats obtenus

Le projet final permet :
	•	de lancer une partie complète de Flip7
	•	de gérer plusieurs joueurs
	•	de distribuer des cartes aléatoirement
	•	de calculer les scores automatiquement
	•	de terminer la partie selon les règles
	•	de sauvegarder les résultats dans un fichier .txt

Le jeu fonctionne globalement correctement en console.

⸻

7. Conclusion

Ce projet nous a permis de mieux comprendre :
	•	la programmation modulaire en C
	•	la gestion de la mémoire et des pointeurs
	•	l’importance de l’organisation du code
	•	le débogage d’un programme complexe

Il nous a également appris à travailler en équipe et à structurer un projet logiciel complet.
